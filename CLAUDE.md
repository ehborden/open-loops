# Open Loops

A personal task tracker built for ADHD-friendly capture, picking, and focus. The owner uses it daily on a phone, a work computer, and a home computer, with real tasks synced between them. Treat changes as changes to a live app with live data.

## How it is built

- The whole app is `index.html`: plain HTML, CSS, and JavaScript. There is no build step, framework, or package manager. Keep it that way unless the owner asks otherwise.
- Hosted on GitHub Pages from `main`, root folder: https://ehborden.github.io/open-loops/. Pushing to `main` deploys it, so only push when the change is tested.
- `manifest.json` and `icon-*.png` support Add to Home Screen.

## Data (do not break this)

- Local copy: `localStorage` key `openloops_v2`. Shape: `{ app, version: 2, current, lists: { Work: {tasks, deleted}, Home: {tasks, deleted} }, settings, timer }`.
- Sync: each list is a file (`work.json`, `home.json`) in the owner's private repo `open-loops-data`, read and written through the GitHub contents API. The token lives only in `localStorage` key `openloops_sync`.
- Merging is item by item. Every task has `updated` (ms timestamp), and removed tasks leave a record in `deleted` (`{id: ms}`). `save()` stamps these on its own by comparing each list to the last saved version (`stampChanges`). Change task data by editing the objects and then calling `save()`. Never write to `localStorage` directly for task data.
- New task fields must be optional. Old data and other devices running an older version will not have them.
- If the stored shape ever has to change, bump the version and migrate the old key the way `loadState()` migrates `openloops_v1`. Devices update at different times, so the old and new shapes have to work side by side.
- Task ids go into `onclick` attributes. Anything loaded from a file or from GitHub passes through `cleanList` / `cleanTask`, and all user text is escaped with `esc()`. Keep both rules for any new field or source of data.

## Features that must keep working

- Backup (Data > Backup) is a file download or, with sync on, "To GitHub" (`backupToGithub`: a dated backup in the data repo right now, replacing today's if there is one, pruned to the newest 12). Both lists as JSON, never including the token. Restore checks the file, shows its date, and asks before replacing. It still accepts first-version backups (`tasks` + `space`).
- With sync on, `autoBackup()` saves `backups/open loops backup YYYY-MM-DD.json` to the data repo after a full sync (both lists) when the newest one is 7 or more days old, then deletes all but the newest 12. It only lists or deletes files matching that name. Restore from GitHub runs the same `restorePayload()` checks as a file restore.
- Steps: a task may have `steps` ([{id, text, done}], ids validated in `cleanTask` because they go into onclick). `step` is kept as a copy of the next unchecked step so older data and older app copies still work. Read with `getSteps()` and write with `setSteps()`, never `t.steps` or `t.step` directly. `getSteps()` also turns a `step`-only task into a one-step list and picks up a `step` changed by an older app.
- Layout: there are no tabs: the home screen is the add box and the notes. The timer card (`#focus-card`) lives in `#side`, above the Closed panel (`.closed-card`, folded by default, open or closed kept in `openloops_view`; on a phone it is drawn at the bottom of the page instead, `.closed-bottom`). Pick for me (`#pick-open`, `openPick` / `closePick`) opens the pick screen as a sheet over the page with one already picked (`pickWeight` leans toward Today, older, quick and low-energy loops); it also has This or that (`_bracket`: a bracket of two loops at a time, buttons, no swiping) and the wheel; the button back to a single pick is Surprise me. There is no swipe mode. Start closes the sheet. At 980px and wider, the page is two columns: the notes on the left and `#side` on the right, with a big ring that drains as time runs down. Below 980px, `#side` sits above the screens, so the timer is at the top, and while idle it is one slim row (`.slim`; More / Less, `_timerOpen`) so the colored notes show on the first screen. Loops are notes in a grid (`.notes`), each with a bar under the tags: its length comes from the time tag (`BAR_LEN`) and its fill from steps checked off; tapping Steps on a note opens it (`_openSteps`) and points the timer at it (`focusId`). Sort buttons above the notes (one Sort button below 980px) are a per-device view setting in `localStorage` key `openloops_view`, not task data. `goFocus(id, true)` starts the timer. When the card is scrolled out of view, the bar at the bottom shows a running timer. The header stays visible.
- Types: each list has an optional `types` array ([{id, name, color, words}]) and `typesAt`, validated in `cleanTypes` and merged like the list name (newer `typesAt` wins) and written in the list file. Until edited, `DEFAULT_TYPES` for Work (Urgent, Ideas, Class, Admin, Projects, Someday) and Home (Urgent, Ideas, Chores, Errands, Health, Someday) are used. A task has an optional `type` (a type id, or `'none'`) and an optional `color` (a plain color picked on the note). `typeOfTask` picks the task's type, else the type with the most words in its name (a tie goes to the first type; computed on screen, not stored). The type tag is on the note and in the edit card. Add with AI asks Claude for the type and stores it. The collapsible Types box under the notes (`#types-box`, open or closed kept in `openloops_view`) holds chips that filter the list by type for this session only (`_typeFilter`, never saved). Both fields pass through `cleanTask`.
- List color: each list has an optional `color` and `colorAt` (a `COLORS` key, validated in `cleanList`, merged by the newer `colorAt`, written in the list file). A 10px bar across the very top of the header (`header::before`, `--band`) takes the color of the open list; the rest of the header stays neutral and there is no rainbow. The Add and Start buttons (`.listbtn`, and the Start in an open note) are a very light tint of that color (`--list-soft`, 16%) with the full color (`--list`) as the outline and dark text, so they stand out from the charcoal buttons without competing with the bar. Defaults: Work teal and Home purple, chosen so a list's header color is not one of its own default type colors. Changed in Data > Lists > Names and colors (the Lists item also opens the Types editor; Restore asks whether it is from a file or from GitHub).
- Delete: the x on a note and on a closed loop (`askDelete` then `deleteTask`) and Delete all closed (`askDeleteAllWins`, `deleteAllWins`) always ask first, remove the task so `save()` leaves the usual deleted record that syncs, are never recorded as closed, and take an Undo snapshot. "Let it go" in the edit card is the older, no-question version.
- Checked-off steps carry an optional `doneAt` (ms) for "steps checked off today" in Closed.
- Adding: one box (`#quick-add`). `splitLoops` / `parseLoop` are the no-AI sorter ("next" splits loops; "steps ... then ..." splits steps). One loop is added directly; several open the check-over screen (`openReview`), where names, steps, time, energy, and Today are all editable in place. It is kept as a draft in `localStorage` key `openloops_draft` until added or discarded. Add with AI and Break it down call the Claude API with the key in `localStorage` key `openloops_ai` (never in backups or sync).
- Editing: tapping a loop's name opens the card (`openEditor`) for name and steps; it saves on every keystroke. Time and energy are tags in the list (`openTagMenu`). Modals opened with kind `'sticky'` (check-over, Break it down) ignore clicks outside so nothing is lost.
- The Data > How to guide (`HELP` in index.html) and README.md say the same thing. Change both when a feature changes.
- Undo reverses only the loops that one action changed (`before` and `after` snapshots), so it never overwrites edits that synced in from another device.
- The focus timer stores an end time, not a countdown, so a refresh does not lose it.

## Testing before you push

Use Playwright with the preinstalled Chromium. Serve the folder over `http://localhost`. Mock `https://api.github.com/**` with `context.route` (a fake store for GET/PUT of contents, with sha checks that return 409 on a mismatch), and use two browser contexts as two devices. At minimum, check: add, complete, delete, and undo on both devices end up the same; offline and then back online; a 401 shows "Sync problem"; backup and restore; no page errors; no sideways scrolling at 375px wide.

## Merging

The owner has said Claude may merge its own pull requests into `main` once the tests above pass, and no longer needs to approve each one. Keep using a branch and a pull request for every change (so there is a record and an easy revert), and tell the owner what went live. Use judgement: merge small, tested changes right away; during a long, multi-step redesign, or when a change could surprise the owner (it moves things around, removes something, or touches how data is stored), hold it and ask first.

## Owner preferences for anything that shows up in the app

- Colors: a neutral off-white background (`--bg: #ecece9`, boxes `#f7f7f5`), always light (no dark mode). Fun, bright colors from the fixed palette `BRIGHT` (Kelly green, blue, purple, teal, pink, red, orange, yellow, grey) go on a thick 12px band down the left of each note; the rest of the note is almost neutral (a 3.5% tint), so a page of notes does not turn into a rainbow. A note takes the color of its type, and the open note is shown a little stronger with an outline (`--n-sel`). Buttons, tabs, links and small labels use charcoal (`--accent: #3a3f42`), so the note colors are the only color on the page; real green (`--green`) is kept only for the "ok" notices (restore ok), and lime is for Today. The Synced pill is charcoal like the other buttons (offline is amber and a problem is red). The title is large (22px, 28px on a computer): "Open Loops" with "Brain Dump and Task Tracker" under it. Each list button has a dot of the list's color. While no timer is running the ring is thin and light, and it turns bold when one runs. Nothing open hides Pick for me and the sort buttons. Confetti uses all of `BRIGHT`. On Pick one, the wheel slices, swipe cards and the picked loop show a very faint tint of the loop's color, with the color itself on the rim or left band. Not bright white. Thin 1px lines: outlines around boxes, buttons, tags, and fields use the darker `--edge` so they stay distinct; dividers inside a box use the lighter `--line`. Small corners, no heavy shadows, lighter type. Not bold or puffy.
- No instruction or over-explaining text on screens (no "Tap X to do Y. Your draft is kept until..."). Short labels only. Explanations belong in How to.

- No em dashes. Use hyphens or rewrite the sentence.
- No emojis.
- Plain, warm wording. No corporate jargon.
- File names use spaces, not underscores (for example `open loops backup 2026-10-10.json`).
